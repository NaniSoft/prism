## Overview

AuthForm01 is a sign-in card: a title, a supporting line, an optional submission
message, the credential fields, an optional remember row and the submit control.

The credential fields arrive as the shared field specification from
`@nanisoft/prism-ui/spec`: an ordered list of `FieldSpecGroup`, each with an
optional heading and an ordered list of `FieldSpec`. A field carries a stable
`key`, a required `label` and a required `kind` drawn from Prism's own input
vocabulary, with optional help, hint, placeholder, autofill hint, disabled flag
and starting value. A login, a registration and a password recovery are one Block,
so nothing forks here: asking for an email draws the `Input` this package ships
and asking for a password draws its `PasswordField`, and a control this package
does not ship is the `slot` arm. The Block is uncontrolled, so the caller reads
the values out of the form element at submit.

The block composes these components:

| Part | Component | Role |
| --- | --- | --- |
| Surface | Card | the panel that centres the form |
| Fields | Field, Label, the shared renderer | a labelled control for every field kind |
| Choices | Checkbox | the remember-me row |
| Feedback | Alert, FieldError | the submission message and the per-field issues |
| Submit | Button | the one action on the card |

The block owns no credentials and makes no request. The submit handler comes from
the consumer, and a submission message is a prop, so the consumer's validation
decides when it appears.

## Usage

```tsx
import { AuthForm01 } from '@nanisoft/prism-ui/blocks/auth-form-01'
import type { FieldSpecGroup } from '@nanisoft/prism-ui/spec'

const groups: readonly FieldSpecGroup[] = [
  {
    fields: [
      { key: 'email', label: 'Email', kind: 'Input', autoComplete: 'email', required: true },
      { key: 'password', label: 'Password', kind: 'PasswordField', required: true },
    ],
  },
]

<AuthForm01
  title="Sign in"
  description="Welcome back. Enter your details to continue."
  submitError={error}
  submitLabel="Sign in"
  groups={groups}
  remember={{ id: 'remember', label: 'Remember me for 30 days' }}
  onSubmit={(event) => {
    event.preventDefault()
    submit(new FormData(event.currentTarget))
  }}
/>
```

## Guidelines

### When to use

Use AuthForm01 for a sign-in, a registration or a password recovery: one centred
credential form, drawn from a declared field list. It works when the screen exists
to collect credentials and send them somewhere.

### When not to use

Do not use it for profile editing or for a record write. Those have a different
job, and the record write form already takes the same field specification.

Do not use it for an account picker or single sign-on landing; that is a different
shape, and `footer` is not the place for it.

### Best practices

- Give every field a `key` that is the value's own key and never the words of the
  label. The form's `FormData` is keyed by it.
- Set `autoComplete` on every field the platform can fill. A password manager and a
  phone keyboard both read it.
- Keep the submission message to one sentence and mark no field with it. A message
  about one control is an entry in `issues`, which marks only that field; bad
  credentials, a locked account and a rate limit are things no field is wrong
  about, so marking two fields tells a reader their correct answers are wrong.
- Reach for the `slot` arm for a control Prism does not ship rather than growing
  the union for one screen.
- Disable the submit control while `pending` and pass `pendingLabel`, so the reader
  sees that work is happening.

### Content guidelines

- The title is a short verb phrase in sentence case: "Sign in", "Continue".
- The description states the outcome, not a policy.
- An error says what to do next: "Enter your email and password to continue."
