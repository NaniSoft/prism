## Overview

PageHeader01 is the title band at the top of an application screen: a
breadcrumb trail, a row of actions, the page title and one supporting line,
closed by a hairline rule.

The block composes these components:

| Part | Component | Role |
| --- | --- | --- |
| Trail | Breadcrumb | the ancestor path, ending on the current page |
| Actions | CtaLink | one primary destination and supporting destinations |
| Title | Typography | the page heading and its supporting line |
| Rule | Separator | closes the band before the working content |

Every step and action is a prop. Both the trail and the actions render native
anchors with a required `href`, so the consumer owns the destination and a control
reads as a link rather than as a command. A control that cannot be a link, such as a
router `Link` or a menu trigger, is the `slot` arm of `actions` and the block places
it where that action sits.

## Usage

```tsx
import { PageHeader01 } from '@nanisoft/prism-ui/blocks/page-header-01'

<PageHeader01
  headingLevel="h1"
  breadcrumbs={[
    { label: 'Projects', href: '/projects' },
    { label: 'Northwind', href: '/projects/northwind' },
    { label: 'Overview' },
  ]}
  title="Overview"
  description="Deployments, usage and the people on this project."
  actions={[
    { label: 'New deployment', href: '/deployments/new' },
    { label: 'Share', href: '/share', variant: 'outline' },
  ]}
/>

// A control that is not a link is a slot, and it says which position it fills.
// `actionsSlot` is gone; it could only ever render before the row's own actions.

<PageHeader01
  headingLevel="h1"
  title="Overview"
  actions={[{ slot: <WorkspaceMenu label="Actions" /> }, { label: 'New deployment', href: '/deployments/new' }]}
/>
```

## Guidelines

### When to use

Use PageHeader01 at the top of a page whose content sits under the app shell. It
works when the page has one name, one short description and a small set of
actions that belong to the page rather than to a single row.

### When not to use

Do not use it as a section heading inside a page. It carries the page title and
a rule that closes a band, so using it mid-page splits one screen into two.

Do not use it in a marketing page. A hero introduces a product; a page header
orients a returning user, and the two carry different weight.

### Best practices

- Set `headingLevel="h1"` on a real page. The default `h2` suits a header
  composed under a heading the document already owns.
- Keep the trail to the ancestors plus the current page. Repeating the title as
  the last step reads as noise.
- Pass one primary action and at most two supporting ones. An action with a
  destination is a link; a menu or a router link goes in the `slot` arm, where it can
  take the position it needs rather than always landing first.

### Content guidelines

- A breadcrumb label is the destination's display name: "Projects", "Settings".
- The title names the screen, not the action: "Overview", not "View overview".
