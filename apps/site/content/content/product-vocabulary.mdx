title: Product vocabulary
description: "The preferred spelling and casing of NaniSoft product terms, and the terms to avoid."

Vocabulary is not standardised across sources. Use the spelling and casing on
this page, and do not guess from another document.

RULE: Always use the spelling and capitalisation shown here in every product
string and in every piece of documentation.

## Sentence case

RULE: Write these terms lowercase in descriptions and body text.

- pack: one of Prism's authored palettes, such as Blush or Sky.
- mode: the appearance of a pack, `light` or `dark`.
- token: a value in the DTCG source.
- component, block and page: the three composition units, in prose. See the
  [Glossary](/content/glossary) for their definitions.

## Title case

RULE: Write these terms in title case in every context.

- Prism
- NaniSoft
- Blush, Mint, Lavender, Sky, Peach: the five pastel pack names, as proper nouns.

## Product terms

- **Prism**: NaniSoft's design system. Never "the Prism system" or "Prism UI".
- **pack**: a palette. Never "theme" for a palette; a theme is a pack in a mode.
- **mode**: `light` or `dark`, written in code font when naming the value.
- **semantic token**: a named intent that aliases into the foundation tier.
- **foundation token**: a raw ramp value that carries no meaning.

## Terms to avoid

RULE: Never use a term in the left column. Use the replacement in the right
column instead.

| Avoid | Use instead |
| --- | --- |
| colourway, color scheme, skin | pack |
| beam-dark, appearance | dark mode, or the mode |
| theme id | pack id |
| primitive, base value | foundation token, or Component |
| wrapper, pass-through | Component |
| catalog (in prose) | catalogue |
| admin panel, admin console | the page's real name |
| pop up, popup, pop-up | dialog |
| login (as a noun) | sign-in |
| e-mail | email |
