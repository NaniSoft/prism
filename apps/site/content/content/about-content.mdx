---

Content is the information in a user interface that works alongside the visual
design. It includes every string a person reads inside a product: labels,
headings, helper text, button text, empty states, error messages, tooltips,
notifications and confirmation dialogs.

RULE: Content is product text. It is not marketing copy, and it does not live on
this documentation site.

## Who this section is for

This section is for anyone at NaniSoft who writes text a customer will read:
designers writing labels, engineers writing empty states and errors, product
managers writing release notes, and support staff writing help text.

RULE: Anyone who writes product copy MUST follow this section. It applies to
first drafts as much as to reviews.

## What this section is not

This section is not a style guide for source code, commit messages or internal
documents. Those have their own conventions. It is also not the design system's
vocabulary; that is the [Glossary](/content/glossary).

## The register

RULE: This section MUST use RFC 2119 keywords (MUST, SHOULD, MAY) so a rule can
be read unambiguously, and it MUST prefix each rule line with `RULE:` so the
rules are machine-greppable.

Outside this section, Prism write in plain language and avoid those keywords.
The difference is deliberate: a rule that a reader must follow is stated as a
rule, and everything else is explanation.
