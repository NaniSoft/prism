title: Composition
description: Choose the right Prism layer and compose components, blocks, and pages without copying design-system code.
---

Prism's three layers answer different questions. Use the smallest layer that owns the job.

## Start with a component

Choose a component when the product needs one accessible control or one visual responsibility.

```tsx
import { Button } from '@nanisoft/prism-ui/components/button';

<Button variant="primary" onClick={save}>
  Save changes
</Button>
```

Do not build a local button variant when the action differs only by consequence. `primary`, `secondary`, `ghost`, `destructive`, and `link` already encode the system's action hierarchy.

## Promote repetition into a block

A block becomes useful when the same product pattern appears across routes or products.

```tsx
import { DataTable } from '@nanisoft/prism-ui/blocks/data-table';

<DataTable
  data={projects}
  getRowKey={(project) => project.id}
  columns={[
    { key: 'name', header: 'Project' },
    { key: 'status', header: 'Status' },
  ]}
/>;
```

Good Prism blocks usually contain one of these patterns:

- application navigation or chrome
- data collection and bulk action
- authentication fields and provider actions
- settings sections with save state
- a documentation example or empty state

## Compose a page last

A page coordinates regions and routes. It should not recreate component behavior.

```tsx
import { DashboardPage } from '@nanisoft/prism-ui/pages/dashboard-page';

<DashboardPage
  title="Overview"
  description="Current delivery and system health."
  nav={navigation}
  metrics={metrics}
  activity={activity}
/>;
```

Pages use structural props so they remain framework-neutral. The application supplies router links, content, and data.

## Composition rules

- Dependencies point downward: pages → blocks → components.
- Keep behavior in the lowest layer that owns it.
- Keep brand color in tokens, not page CSS.
- Keep application data and routing in the application.
- Prefer a semantic prop over a chain of local class overrides.
- Never copy Prism source into an application when the npm package can own it.
