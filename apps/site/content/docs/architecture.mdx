Prism is organized as owned source, not as a generated mirror of another design system.

## The package boundary

`@nanisoft/prism-ui` is the only UI package an application imports. It uses accessible Base UI behavior internally, then applies Prism's own props, component anatomy, CSS recipes, tokens, and composition patterns. The primitive layer is not re-exported as public API.

That boundary gives a consuming project three guarantees:

1. No direct dependency on a second component library.
2. No upstream visual defaults leaking between Prism and a host application.
3. One version line for behavior, design, docs, and machine-readable source.

`@nanisoft/prism-tokens` remains a pure data package for theme packs, CSS variables, and Figma export. Applications normally do not need to import it directly because the common factories and pack data are re-exported from `@nanisoft/prism-ui`.

## Three composition layers

### Components

A component owns one visual responsibility and the accessible behavior required to perform it. Examples: `Button`, `Field`, `Select`, `Dialog`, and `Table`.

### Blocks

A block is a repeated product pattern assembled from components. Examples: `DataTable`, `AuthForm`, `ApplicationShell`, and `SettingsPanel`. Blocks accept serializable structural props and do not depend on Next.js or a docs framework.

### Pages

A page is a complete structural composition assembled from blocks and components. Examples: `DashboardPage`, `DocsShell`, `SettingsPage`, and `AuthPage`. Pages still take framework-neutral view models; the application maps its router, content loader, and data layer into those models.

The dependency direction is one-way:

```text
pages → blocks → components → accessible primitives
```

Sibling layers do not import each other. Shared UI moves downward.

## Source-to-corpus pipeline

```text
Prism catalog + TypeScript declarations + MDX examples
                    ↓
              prism-llms build
                    ↓
       llms.txt · Markdown mirror · data.json
                    ↓
         Prism MCP · site docs · agent tooling
```

The catalog in `packages/ui/src/catalog.ts` is the shared item list. The docs index, generated content, LLM corpus, and MCP all project that list, so a component cannot silently exist in one surface and disappear from another.

## Styling contract

Prism ships plain CSS and semantic custom properties. Components expose stable `prism-*` classes and state attributes for layout composition, but they do not require selector surgery into internal DOM.

- Use documented `className` hooks for placement and spacing.
- Use theme factories for semantic color and type changes.
- Do not override private descendant selectors.
- Do not import the internal primitive package.
